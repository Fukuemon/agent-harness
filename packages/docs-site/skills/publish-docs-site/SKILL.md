# publish-docs-site

文書のサイトのジェネレーターの出力、カタログのビルドの出力、図の出力を、1 つの出力のディレクトリのサブパスに並べて、1 つの公開先へ出す。  
組み立てと保護の確認のスクリプトは、このスキルの `assets/scripts/` にあり、導入のスキルが利用者のリポジトリの `scripts/` へ写す。  
ジェネレーターと公開先に依る設定とワークフローの雛形は、`references/` の下に、ツールの名前のディレクトリで置いてある。

## 始める前に読むもの

- 利用者の `context/project.yml` の `docs_site`。なければ、下の「値」を利用者に尋ねて書く。
- 利用者の `context/operations.md` の Environments と Secrets。公開先と、秘密の値の置き場を持つ。食い違うときは context に従う。

## 値

```yaml
docs_site:
  parts:
    - { path: site, subpath: "", build: <文書のサイトを作るコマンド> }
    - { path: <カタログのビルドの出力>, subpath: catalog, build: <カタログを作るコマンド> }
    - { path: <図の出力>, subpath: erd, exclude: [<配信に使わないファイル>] }
  tokens_css: <意味のトークンの CSS>
```

- `parts` は、並べるもの。`path` はリポジトリのルートからの相対パス、`subpath` は出力の中の置き場で、空の文字列がサイトのルートになる。
  - `build` は `path` を作るコマンド。`exclude` は写さないファイルとディレクトリの名前。どちらも省ける。
- `tokens_css` は、サイトの色に当てる意味のトークンの CSS。デザインシステムがなければ省く。
- 尋ねるときは、値のファイルに既にあるほかのキーのうち、トークンの CSS とカタログのビルドの出力に当たるパスを候補に示す。2 つのキーに同じ値を書き、片方を変えたらもう片方も直す。
- schema はパッケージの `schemas/docs-site.schema.json` にある。

## 組み立て

```sh
node scripts/build-docs-site.mjs --out <出力のディレクトリ> [--build]
```

- `--build` は、並べる前に各 part の `build` をリポジトリのルートで実行する。CI では付け、手元で出力を作ってあるときは省く。
- 出力のディレクトリは、並べる前に消す。`parts` の `path` と重ねない。
- 終了コード 0 は並べた。1 は値の誤りか並べるものがないので、メッセージのとおりに値を直すか `build` を実行する。2 は値のファイルが読めないか、`build` が失敗した。
- 文書の中のリンクは相対の URL にする。サブパスに置いたカタログと図へのリンクは、ジェネレーターの手元のプレビューでは開けない。

## 公開

- 既定のブランチへ取り込んだときだけ公開する。pull request ごとのプレビューは出さない。
  - プレビューは pull request のコードへ公開のトークンを渡す。書き込みの権限を持つ人は、ワークフローを書き換えてトークンを読める。
- 公開のトークンは CI の secrets に置き、権限は 1 つの公開先の中身と設定の編集だけに絞る。漏れたときに書き換えられるものを、そのサイトに限るためである。
  - トークンで保護の設定を変えられないようにする。
- 文書の元がリポジトリの全体にあるときは、ワークフローを変えたパスで絞らない。

## 保護

- 保護は公開先の単位で掛ける。アカウントの全体に掛けると、同じアカウントの公開しているほかのサイトも開けなくなる。
- 公開先の名前を変えると、新しい公開先が保護なしで出ることがある。名前を変える前に、新しい名前で保護を掛ける。
- 保護されていることは、公開のたびに次で確認する。

  ```sh
  node scripts/check-docs-site-protection.mjs <サイトの URL> <保護した中身にだけある文字列>
  ```

  - 認証のない要求でリダイレクトをたどり、サイトと別のオリジンの認証の画面に着き、応答に文字列がなければ終了コード 0 になる。
  - 1 は保護されていない。公開先の保護の設定と、公開先の名前を確認する。2 は引数の誤りか、要求が失敗した。
  - 文字列に、サイトの名前と公開先の名前を使わない。認証の画面にも出ることがある。

## 雛形

利用者のリポジトリのジェネレーターと公開先に合うディレクトリを選び、写すかを利用者に尋ねる。どれも合わなければ、近い雛形を元に書く。

| ディレクトリ | 持つもの |
| --- | --- |
| `references/zensical/` | ジェネレーターの設定、トークンを当てる CSS、モックの高さを合わせるスクリプト |
| `references/cloudflare-workers/` | 公開先の設定、公開と保護の確認のワークフロー |

- 雛形の `<...>` は、利用者の値に置き換える。ナビゲーション、書体、公開先の名前は、雛形に入れていないので利用者が決める。
- トークンを当てる CSS の変数の名前は、利用者の意味のトークンの名前に置き換える。
- モックの高さを合わせるスクリプトは、モックが送るメッセージの `source` と同じ値にする。利用者のリポジトリに同じ働きのスクリプトが既にあれば、写さずにそれを読む。
- 公開先の用意（アカウント、公開先、トークン、保護）の手順は、利用者のリポジトリの、公開の設定の隣の README に書く。
