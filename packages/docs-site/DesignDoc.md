# 文書のサイト

## Overview

パッケージ docs-site は、リポジトリの文書、カタログ、図を 1 つのサイトに並べ、既定のブランチへ取り込んだら公開先へ公開する構成を持つ。全体像は [agent-harness Design Doc](../../design/DesignDoc.md) にある。

## Scope

- 持つもの: サイトに並べるものの組み立て、公開のワークフロー、保護の確認、モックの埋め込みとトークンの当て方。
- 持たないもの: 文書の中身と形（docs と screens が持つ）。カタログの中身（design-system と利用者が持つ）。公開先の名前、ナビゲーション、書体（利用者が決める）。

## Design

### 組み立て

`docs_site.parts` に並べたもの（文書のサイトのジェネレーターの出力、カタログのビルドの出力、図の出力）を、1 つの出力のディレクトリのサブパスに並べる。  
組み立てのスクリプト `build-docs-site.mjs` は、並べる前に出力のディレクトリを消し、`parts` を並べた順に写す。`--build` を付けると、各 part の `build` のコマンドを先に実行する。  
ワークフローは part ごとのコマンドを持たず、スクリプトに `--build` を渡すだけにする。並べるものを足すときに、値のファイルだけを直せば済む。

### 公開

既定のブランチへ取り込んだら、組み立てた出力を公開先へ公開する。pull request ごとのプレビューは出さない。  
プレビューは pull request のコードへ公開のトークンを渡すため、書き込みの権限を持つ人がワークフローを書き換えてトークンを読める。  
公開先の秘密の値は CI の secrets に置き、権限は 1 つの公開先の編集だけに絞る。

### 保護

公開先の単位でアクセスの保護を掛ける。  
保護の確認のスクリプト `check-docs-site-protection.mjs` は、認証のない要求でリダイレクトをたどり、サイトと別のオリジンの認証の画面に着き、応答に保護した中身の文字列がないことを確認する。ワークフローは公開のたびにこのスクリプトを流す。

### ファイルの置き場

導入のスキルが `assets/` を全部、利用者のリポジトリへ写すことに合わせて決める。

- 組み立てと保護の確認のスクリプトは、どのジェネレーターと公開先でも使うので、スキル publish-docs-site の `assets/scripts/` に置く。テストは写さないので、パッケージの `scripts/` に置く。
- ジェネレーターと公開先に依る設定とワークフローは、利用者が選んで写すので、`references/` の下にツールの名前のディレクトリで置く。中は、利用者のリポジトリでの置き場と同じパスにする。
  - ADR-0023: [検証、E2E、デザインシステム、画面仕様書、文書のサイトを関心ごとのパッケージにし、組み合わせは値のファイルのキーで渡す](../../adr/0023-concern-packages.md)
- 公開先の用意と保護の手順書は、ツールの名前を多く含むので、`examples/docs-site/` に置く。利用者は、写した設定の隣の README に置く。
- 画面仕様書のモックの高さを合わせるスクリプトは、ジェネレーターの雛形と一緒に置く。モックが送るメッセージの `source` は、プロダクトに依らない `screen-mock` にする。

## Interface

- 読むキー: `docs_site.parts`（並べるもののパス、サブパス、作るコマンド、写さない名前）、`docs_site.tokens_css`（サイトの色に当てるトークンの CSS）。schema は `schemas/docs-site.schema.json` にある。スクリプトは、schema の規則に、サブパスの重なりの確認を足して検証する。
- 写す雛形: 組み立てのスクリプトと保護の確認のスクリプト（`assets/`）。ジェネレーターと公開先ごとの設定とワークフロー（`references/` の下から選ぶ）。
