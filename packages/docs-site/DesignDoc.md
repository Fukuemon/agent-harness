# 文書のサイト

## Overview

パッケージ docs-site は、リポジトリの文書、カタログ、図を 1 つのサイトに並べ、既定のブランチへ取り込んだら公開先へ公開する構成を持つ。全体像は [agent-harness Design Doc](../../design/DesignDoc.md) にある。

## Scope

- 持つもの: サイトに並べるものの組み立て、公開のワークフロー、保護の確認、モックの埋め込みとトークンの当て方。
- 持たないもの: 文書の中身と形（docs と screens が持つ）。カタログの中身（design-system と利用者が持つ）。公開先の名前、ナビゲーション、書体（利用者が決める）。

## Design

### 組み立て

`docs_site.parts` に並べたもの（文書のサイトのジェネレーターの出力、カタログのビルドの出力、図の出力）を、1 つの出力のディレクトリのサブパスに並べる。  
組み立てのスクリプト `build-docs-site.mjs` は、並べる前に出力のディレクトリを消し、`parts` を並べた順に写す。`--build` を付けると、各 part の `build` のコマンドを先に実行する。  
ワークフローは part ごとのコマンドを持たず、スクリプトに `--build` を渡すだけにする。並べるものを足すときに、値のファイルだけを直せば済む。  
出力のディレクトリの下に Git で追跡しているファイルがあれば、消さずに止める。part の出力どうしでファイルがぶつかったときも、上書きせずに止める。

スクリプトは依存を持たず、値のファイルを `read-docs-site-config.mjs` で読む。利用者のリポジトリに YAML のライブラリがなくても動かすためである。  
読む形は、`parts` をブロックの配列にし、各要素をブロックのマッピングで書く形に限る。`exclude` だけは、引用符のない名前のフローの配列にする。ほかの形は、値の誤りと分けて終了コード 2 で止める。

### 公開

既定のブランチへ取り込んだら、組み立てた出力を公開先へ公開する。pull request ごとのプレビューは出さない。  
プレビューは pull request のコードへ公開のトークンを渡すため、書き込みの権限を持つ人がワークフローを書き換えてトークンを読める。  
公開のトークンは、既定のブランチの実行からだけ読める秘密の値の置き場に置き、権限は 1 つの公開先の編集だけに絞る。ワークフローの条件だけで絞ると、条件を外したワークフローを別のブランチへ push してトークンを読めるためである。

### 保護

公開先の単位でアクセスの保護を掛ける。  
保護の確認のスクリプト `check-docs-site-protection.mjs` は、認証のない要求でリダイレクトをたどり、指定したホストの認証の画面に着き、途中と最後の応答に保護した中身の文字列がないことを確認する。ワークフローは公開のたびにこのスクリプトを流す。  
スクリプトは 1 つの URL を見る。サブパスに置いた part は、URL と文字列を替えて part ごとに流す。

### ファイルの置き場

導入のときにどの利用者にも同じパスへ写すものは `assets/` に、利用者が選んで写すものは `references/` の下に置く。

- ADR-0025: [写す先が利用者ごとに違うテンプレートは references/ に置き、キーを尋ねる場所と schema の有無はパッケージが決める](../../adr/0025-templates-keys-and-schemas.md)

- 組み立てと保護の確認のスクリプトは、どのジェネレーターと公開先でも使い、どの利用者も `scripts/` に置くので、スキル publish-docs-site の `assets/scripts/` に置く。テストは写さないので、パッケージの `scripts/` に置く。
- ジェネレーターと公開先に依る設定とワークフローは、利用者が選んで写すので、`references/` の下にツールの名前のディレクトリで置く。中は、利用者のリポジトリでの置き場と同じパスにする。publish-docs-site の手順が、写すかを利用者に尋ねて写す。
  - ADR-0023: [検証、E2E、デザインシステム、画面仕様書、文書のサイトを関心ごとのパッケージにし、組み合わせは値のファイルのキーで渡す](../../adr/0023-concern-packages.md)
- 公開先の用意と保護の手順書は、ツールの名前を多く含むので、`examples/docs-site/` に置く。利用者は、写した設定の隣の README に置く。
- 画面仕様書のモックの高さを合わせるスクリプトは、ジェネレーターの雛形と一緒に置く。モックが送るメッセージの `source` は、プロダクトに依らない `screen-mock` にする。
  - screens も同じスクリプトを配る。2 つのパッケージは互いに依存しないので両方に置き、どちらのスキルも、同じ働きのスクリプトが既にあれば足さない。2 つのコメントを除いたコードが同じことは、このリポジトリのテスト `scripts/embed-mock.test.mjs` が確認する。

## Interface

- 読むキー: `docs_site.parts`（並べるもののパス、サブパス、作るコマンド、写さない名前）、`docs_site.tokens_css`（サイトの色に当てるトークンの CSS）。schema は `schemas/docs-site.schema.json` にある。スクリプトは、schema の規則に、サブパスの重なりと入れ子の確認を足して検証する。
  - 導入のスキルは持たない。キーは、publish-docs-site を初めて使うときに利用者に尋ねて書く。
  - schema を持つのは、組み立てのスクリプトが値の形を検証し、そのテストが schema と同じ合否になることを確認するためである。
  - ADR-0025: [写す先が利用者ごとに違うテンプレートは references/ に置き、キーを尋ねる場所と schema の有無はパッケージが決める](../../adr/0025-templates-keys-and-schemas.md)
- 写す雛形: 組み立てのスクリプトと保護の確認のスクリプト（`assets/`）。ジェネレーターと公開先ごとの設定とワークフロー（`references/` の下から選ぶ）。
