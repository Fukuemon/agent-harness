# 開発の準備

必要なランタイムとツールの名前と版、最初に実行するコマンドを書く。

## コミットするとき

- コミットの前に動くチェックと、その直し方を書く。
- コミットメッセージの形式を書く。

## ブランチとリリース

- 作業用のブランチの名前の付け方を書く。
- 保護するブランチと、直接コミットしてよいかは、`context/project.yml` の `guardrails.protected_branches` で宣言する。ここには本文を書かず、その値を指す。
- バージョンの付け方と、リリースの手順を書く。

## issue と pull request

- 作業の始め方を書く。issue の種類、ラベル、pull request との対応。
- 規約の本文は `context/` に置き、ここからはリンクする。
