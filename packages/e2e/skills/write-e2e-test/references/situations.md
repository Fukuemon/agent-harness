# 場面ごとの書き方

テストのツールの API の名前は、利用者の `context/testing/e2e.md` にある。

## 新しいタブを開く画面

画面が新しいタブを開くときは、ブラウザの API を差し替えずに確認できる。新しいタブは、テストのツールのタブを開いたときのイベントで受け取る。

- タブをまたいで引き継がれるはずの値は、ページを読み込むたびに実行するスクリプトで、元のタブにだけ入れる。両方に入れると、引き継がれたかを確認できない。
  - ページのスクリプトから新しく開いたタブは、`sessionStorage` のコピーを受け取り、`window.name` は受け取らない。
- 画面の中の移動は、URL の path を開いて作る。アプリが path で画面を分けていないときは、利用者の context の書き方に従う。
- 観点は、遷移先の画面の既存の spec に足す。別のファイルに切ると、遷移先の画面を描くための準備を作り直すことになる。
- ローカルの開発サーバに向けて並べて流すと、画面のコンパイルが詰まり、画面を開く操作が時間切れになる。worker の数は、利用者の context に従い、増やさない。

## 時間で動く画面

一定の間隔で取り直す画面は、実際の時間を待たずに、テストのツールで時計を差し替えて進める。

- 時計を差し替えるのは、要るテストだけにする。差し替えると、アプリのほかの遅らせる処理も止まる。
- 日付だけを固定したいときは、時計を進めずに時刻を固定する。
- 固定する時刻は、テストを流すマシンのタイムゾーンで日付が変わらない時刻にする。UTC の 06:00 は、UTC から UTC+14 まで、同じ日付になる。

## testid を付ける

testid は、テストのコードではなくアプリのコンポーネントに付ける。名前の付け方は、利用者の `context/testing/e2e.md` に従う。  
共通のコンポーネントに付けるときは、付けた先が思った要素にならないことがある。

| 場面 | 起きること | 付け方 |
| --- | --- | --- |
| 画面の接頭辞を自分で決める共通の枠を、入れ子で使う | 同じ testid が 2 つ出て、testid で拾う操作が複数の要素に当たって落ちる | 外側の枠が印を渡し、内側の枠は、明示で渡されたときだけ付ける |
| 一覧の見出し | 表示の文言から作ると、文言を変えたときに指せなくなる | 列のキーから作る |
| コンポーネントの中のボタンや入力欄 | 渡した属性は、コンポーネントの外側の要素にしか付かない | コンポーネントに、中の要素へ付けるための引数を足す |
| アプリのフレームワークが描かない DOM（外部のライブラリが描く枠など） | 属性を宣言では付けられない | その DOM を作る処理の中で付けるか、`selectors/` に指し方を置く |
| 選ばれているかが変わるボタン | 見た目の違いしか無いと、テストが待てない | 選ばれているかを `aria-pressed` で出す。選ばれていないときも `"false"` を出す |

共通のコンポーネントに渡した testid が、中のどの要素に付くかは、コンポーネントごとに違う。付く先は、コンポーネントの文書コメントを読んで確認する。
