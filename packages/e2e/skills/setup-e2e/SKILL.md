# setup-e2e

core の導入のスキル setup-agent-harness を先に実行しておく。`context/testing/e2e.md` の骨組みは、そのスキルが写す。  
既にあるファイルを書き換えるときと、依存を足すときは、差分を利用者に見せてから行う。

## kit のバージョン

入れる kit の名前とバージョンは、このスキルのディレクトリの `kit-version.json` にある。  
e2e のスキルと kit は同じバージョンで出るので、バージョンを範囲にせず、この値に固定して入れる。範囲にすると、スキルが前提にしていない kit が入る。

## kit を入れる

1. E2E のテストのディレクトリを決める。
   - `context/project.yml` の `e2e.dir` を読む。書かれていなければ、既にあるテストのツールの設定ファイルを探し、見つかったディレクトリを候補にして利用者に尋ねる。
   - 決まったら `e2e.dir` に書く。以後の手順では、このディレクトリを `<e2e>` と書く。
2. テストのツールを決める。
   - `<e2e>` か、リポジトリのルートの依存に入っているテストのツールを使う。入っていなければ、利用者に尋ねる。
   - 雛形は、このスキルの `references/` の下の、ツールの名前のディレクトリにある。合うディレクトリがなければ、雛形を写す手順を飛ばし、kit の README の使い方を利用者に見せる。
3. kit を入れる。
   - パッケージマネージャーは、`<e2e>` かリポジトリのルートのロックファイルから決める。
   - `kit-version.json` の名前とバージョンを、開発の依存に固定で足す。
   - lint の規則を使うなら、lint のツールと、TypeScript を読むパーサーも足す。既に入っていれば足さない。
4. 入れた kit の `package.json` の `peerDependencies` と、入っているテストのツールのバージョンを比べる。範囲の外なら、上げるかを利用者に尋ねる。尋ねずに上げない。

## 雛形を写す

ツールの名前のディレクトリの中は、`<e2e>` からの相対パスで置いてある。ファイルの名前は、そのツールと lint のツールの既定の名前にしてある。

| 雛形 | 役割 |
| --- | --- |
| テストのツールの設定 | テストのプロジェクトを、準備、E2E、エビデンスの 3 つに分ける。CI は E2E だけを流し、エビデンスは pull request を作るときに手元で撮る |
| lint の設定 | テストの書き方の規則を、`<e2e>` の `tests/` の下に掛ける |
| `tests/fixtures/evidence.ts` | エビデンスを撮る spec から kit を呼ぶ薄い層。アプリの名前、URL、viewport、置き場を持つ |
| `tests/fixtures/timeouts.ts` | 待つ時間の名前。lint の規則が、ほかのファイルの待つ時間の数値を止める |

1. 写すファイルを利用者に尋ねる。既にあるファイルは上書きせず、雛形との差分を見せて、取り込むところを決める。
2. 写したファイルの `<>` の値を、利用者に尋ねて埋める。リポジトリのルートへの相対パスは、写した位置から決める。
3. CI のワークフローがあれば、E2E のプロジェクトだけを流す手順を足すかを尋ねる。ブラウザのエンジンを入れる手順と、アプリを起動する手順も要る。起動の仕方が分からなければ、利用者に尋ねる。

## context を埋める

`context/testing/e2e.md` の骨組みの、次のセクションを、決めた値で埋める。案内のコメントは消す。骨組みがなければ、setup-agent-harness を先に実行するよう伝える。

- Test Tool: テストのツールと kit の入れ方。write-e2e-test が一般の語で書いた確認、testid での要素の拾い方、通信の差し替え、新しいタブの受け取り、時計の差し替えに当たる API の名前。
- Lint Rule Options: lint を流すディレクトリと、規則に渡した値。
- Running Tests: 流すコマンド、プロジェクトの分け方と CI で流す範囲、worker の数とその理由、エビデンスの置き場。

ほかのセクションは、決まっていなければ空のまま残し、決める時期を利用者に伝える。

## 確認する

1. lint と型のチェックを `<e2e>` で流す。
2. 雛形を写したら、E2E のプロジェクトで spec を 1 本だけ流す。spec がなければ、流さずに、流す手順を利用者に伝える。
3. 結果を利用者に見せる。

## e2e を上げたとき

パッケージ e2e のバージョンを上げたら、`kit-version.json` のバージョンを読み、開発の依存の kit を同じバージョンに上げる。  
雛形が変わったかは、写したファイルと、このスキルの `references/` の雛形との差分で見る。取り込むところは利用者と決める。

## してはいけないこと

- kit をバージョンの範囲で入れない。
- 利用者のテストのツールのバージョンを、尋ねずに上げない。
- 既にある設定ファイルを上書きしない。
