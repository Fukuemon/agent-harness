# カタログ

カタログは、はじめに、トークン、コンポーネント、パターン、画面の 5 つのページに分け、この順にサイドバーに並べる。

| ページ | 書くこと |
| --- | --- |
| はじめに | 原則、アクセシビリティの基準 |
| トークン | 色の階調と意味のトークン、文字、余白、角丸、影 |
| コンポーネント | コンポーネントごとに、使う場面、使わない場面、Do と Don't、変種、状態、キーボードの操作 |
| パターン | コンポーネントを組み合わせた形（入力のダイアログ、絞り込みの一覧）。狭い画面と広い画面の例 |
| 画面 | 画面のコンポーネント |

- 題は、ファイルの配置先から機械的に決める。例を作るときに分類を判断しない。配置先と題の対応は、デザインシステムの文書の「題の決め方」の表にある。
- コンポーネントの「状態」には、デザインシステムの文書のそのコンポーネントのセクションに並べた状態を、全部例にする。読み込み中とエラーのように、データで決まる状態も、ダミーのデータで作る。
- テーマがあれば、カタログでテーマを切り替えられるようにし、アクセシビリティの自動チェックをテーマごとに動かす。
- カタログの原稿は、デザインシステムの文書の見本にする。規則の本文はデザインシステムの文書にだけ書き、カタログからリンクする。
- カタログに載せるのは、コンポーネントとダミーのデータだけにする。開ける人の範囲は変わりうるためである。
  - 人と組織の名前はダミーの値にし、実際の画面やデータベースからコピーしない。
  - API を呼ぶ例を作らない。
  - カタログの原稿に、URL、ホスト名、シークレットを書かない。デザインシステムの文書と画面仕様書からカタログへのリンクは、`design_system.catalog_url` で書く。
