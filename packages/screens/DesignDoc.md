# 画面仕様書

## Overview

パッケージ screens は、画面ごとに、何を表示し、どの状態があり、どう操作できるかを、文書と操作できるモックで書く型を持つ。全体像は [agent-harness Design Doc](../../design/DesignDoc.md) にある。

## Scope

- 持つもの: 画面仕様書の規約とテンプレート、画面の ID の形、モックの共通のファイル（番号の印、デバイスの切り替え、属性で付ける操作、ワイヤーフレームの CSS、埋め込んだモックの高さの受け渡し）、規約の点検、画面仕様書を書くスキル。
- 持たないもの: 処理と通信（機能の Design Doc が持つ）。提供する機能の一覧（PRD が持つ）。トークンの値（design-system と利用者が持つ）。画面の ID のドメインの語（利用者の目次が持つ）。

## Design

### 画面ごとのファイル

画面ごとに 1 つのディレクトリを置く。

| ファイル | 持つもの |
| --- | --- |
| `index.md` | 状態ごとのタブ、構成要素の表（番号、種別、要素名、仕様）、要素ごとのセクション（値のソース、活性の条件、表示の条件、カタログ、操作） |
| `api.md` | 画面の型の項目と、API の項目の対応 |
| `mocks/` | 状態ごとに 1 枚の静的な HTML |

状態のタブは `=== "<状態の名前>"` の行と 4 つの空白の字下げで書き、点検もこの形で読む。文書のサイトがこのタブの記法を描けないときは、タブが見出しのない字下げのブロックとして表示される。

### スキルと雛形

スキルは write-screen-spec の 1 つにする。規則は利用者のリポジトリへ写す規約（`rules.md`）が持ち、スキルは作業の順と確認の方法だけを持つ。規約は利用者が直して育てるので、スキルに写すと食い違うためである。

導入のスキルは、配置されたスキルの `assets/` を全部、同じパスで利用者のリポジトリへ写す。写す先を値のファイルで変えられず、既にあるファイルは更新しない。そのため雛形は `assets/` に置かず、`references/screens/` に置き、このスキルの `scripts/copy-screen-templates.mjs` が `screens.dir` へ写す。

- ADR-0025: [写す先が利用者ごとに違うテンプレートは references/ に置き、キーを尋ねる場所と schema の有無はパッケージが決める](../../adr/0025-templates-keys-and-schemas.md)

- `rules.md`: 規約。
- `index.md`: 目次。画面の一覧と、画面の ID の規則（`<ドメイン>-<種類>` の形と種類の語）を持つ。ドメインの語は利用者が足す。
- `_template/`: 仕様書、API との対応、モック、画面の CSS のテンプレート。
- `_common/`: モックの共通のファイル。

写すスクリプトは、既にあるファイルを上書きしない。規約、目次、テンプレートは、写した後は利用者が直すためである。  
`_common/` の `mock.js`、`interact.js`、`mock.css`、`embed-mock.js` は、パッケージが直す共通の処理なので、違えば差分を出し、`--update` のときだけ上書きする。`wireframe.css` は、利用者が `:root` にトークンを当てるので、無いときだけ写す。  
screens を後から入れた利用者も、パッケージを更新した利用者も、同じスクリプトで雛形と共通の処理を受け取る。

`screens` のキーは、別の導入のスキルを作らず、write-screen-spec が初めて使われたときに利用者に尋ねて書く。キーは 4 つで、読むのは write-screen-spec と点検のスクリプトだけなので、スキルを増やすと説明の分だけ毎回のコンテキストを使うためである。

### モック

モックは静的な HTML を基準にし、コーディングエージェントが書く。デザインのツールのファイルは参照してよいが、基準にしない。  
モックは、トークンの CSS と共通の CSS だけを読み、外部の URL を読まない。要素に番号と、テストが使う識別子を付ける。テストの識別子は、モックに付けたものを元にする。

- 色、角丸、書体は `wireframe.css` の `--wf-*` だけで書く。`wireframe.css` の `:root` は、トークンの CSS が無くても描ける中立の値を持つ。トークンの CSS を読む利用者は、`:root` で意味のトークンを `--wf-*` に当てる。トークンの段の分け方は design-system が持ち、screens はトークンの名前を知らない。
- モックは、仕様書のページに iframe で埋め込まれたとき、中身の高さを `postMessage` で親のページへ送る。メッセージの `source` は `screen-mock` にし、送る側の `mock.js` と受ける側の `embed-mock.js` の定数で揃える。プロダクトの名前を含めないので、利用者ごとに変える必要がない。
- `embed-mock.js` は、仕様書のページを描くサイトが読む。サイトの設定は利用者が持つので、screens は読み込むファイルだけを配る。
- 受ける側を別に持つサイトとは、次の値を揃える。値が揃っていれば、サイトの受ける側をそのまま使い、`embed-mock.js` を重ねて読まない。
  - メッセージは `{ source: "screen-mock", type: "resize", height }` で、`height` は中身の高さの px の数。
  - 受ける側は、送ってきた window を `contentWindow` に持つ `iframe.mock` の高さを、`height` に枠線の幅を足した値にする。

### 点検

点検のスクリプト `check-screens.mjs` は、スキルの `scripts/` に置く。スキルと一緒に配置先へ写るので、利用者は配置先から、リポジトリのルートで呼ぶ。  
配置先には依存のライブラリが無いので、`context/project.yml` は `screens:` の下の 1 段のスカラーだけを自前で読む（`read-screens-config.mjs`）。flow の形とブロックのスカラーは読めないので、終了コード 2 にする。schema は `schemas/screens.schema.json` に置き、テストで値の形を確認する。

規約の点検は、名前、番号、操作の属性、禁止の記述、テンプレートの消し忘れを見る。カタログの欄のリンクと、テストの識別子は、キーで場所を受け取ったときだけ見る。

- `screens.catalog_url` があるときは、カタログの欄にリンクがあり、全てのリンクがその URL の下（同じ URL か、後ろが `/`、`?`、`#` で続く）にあることを見る。
- `screens.e2e_dir` があり、全ての画面を見るときは、そのディレクトリのテストのコードの `getByTestId(` の引数が、どれかのモックの `data-testid` にあることを見る。コメントの中の呼び出しと、依存とテストの結果のディレクトリは読まない。
  - 照らすのは、引数の先頭のリテラルだけにする。文字列は同じ値か `{…}` の形に、テンプレート文字列と `/^…/` は、先頭のリテラルを始まりに当てる。
  - 変数や、`${…}` で始まるテンプレート文字列は、照らさずに件数だけを出す。testid の接頭辞を引数で受けるテストのコードを、違反にしないためである。
- リンクの先のページがカタログにあるかは見ない。ページの ID を作るには、カタログのツールの内部の API を呼ぶ必要がある。内部の API はバージョンごとに変わりうるうえ、ツールに依るコードを汎用の点検に入れることになるためである。ページの有無は、利用者のカタログのビルドとリンクのチェックで確認する。

## Interface

- 読むキー
  - `screens.dir`: 画面仕様書の置き場。既定は `docs/screens`
  - `screens.tokens_css`: モックが読むトークンの CSS。省くとモックはトークンの CSS を読まない
  - `screens.catalog_url`: カタログの URL。省くとカタログの欄のリンクを見ない
  - `screens.e2e_dir`: テストの識別子を照らすディレクトリ。省くとテストの識別子を見ない
- 点検: `node <配置先>/write-screen-spec/scripts/check-screens.mjs [画面のディレクトリ]...`。終了コードは 0 が違反なし、1 が違反あり、2 が設定の誤り。
- 雛形を写す: `node <配置先>/write-screen-spec/scripts/copy-screen-templates.mjs [--update]`。終了コードは 0 が完了、1 が共通の処理に差分がある、2 が設定の誤り。
- 写す雛形: 規約、目次と画面の ID の規則、テンプレート、モックの共通のファイル。
