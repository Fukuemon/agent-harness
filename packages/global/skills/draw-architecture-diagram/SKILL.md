# draw-architecture-diagram

構成図は、draw.io で編集できる SVG にする。SVG の本体に描画の結果を持ち、ルートの `content` 属性に draw.io のモデル（`mxGraphModel`）を持つ形である。

- Markdown に画像として埋め込める。ホスティングサービスとノートのアプリで、そのまま表示される。
- draw.io のデスクトップのアプリ、エディタの拡張機能、ノートのアプリの draw.io のプラグインで開くと、利用者が編集できる。
- Mermaid や HTML の図は、クラウドのアイコンを使えず、利用者が GUI で直せない。構成図には使わない。

## 進め方

1. 図の目的を 1 つに決め、図を分ける（下の「図の分け方」）。
2. 置き場と名前を決める（下の「置き場」）。
3. `mxGraphModel` を書く。スタイルの文字列は [references/styles.md](references/styles.md) から取る。
4. `scripts/render-drawio-svg.mjs` で SVG に描画し、`--png` の画像を見る。
5. 線と文字の重なり、折り返し、はみ出しを直し、4 に戻る。重なりが無くなるまで繰り返す。
6. 文書に埋め込む。

## 図の分け方

1 枚の図には 1 つの目的だけを描く。混ぜると、線が増えて読めなくなる。

| 図 | 描くもの | 描かないもの |
| --- | --- | --- |
| 実行時の構成図 | どこで動くか、何と何がどのプロトコルで通信するか | IaC の置き場、CI の流れ |
| 管理の境界図 | どのリポジトリと state が何を持つか、変更をどう流すか、IaC にしないもの | 通信のプロトコル |
| 処理の流れの図 | 1 つの操作の順序（番号を振る） | 常に存在する構成の全体 |

- 環境（dev、prod）で形が違うなら、環境ごとに描く。同じなら、タイトルに「dev と prod で同じ形」と書く。
- 1 枚の要素が 30 を超えたら、分けられないかを考える。

## 描き方

出典: AWS Architecture Icons の deck、[AWS Networking Best Practices の Conventions](https://aws.github.io/aws-networking-best-practices/community/conventions/)、[C4 model の Notation](https://c4model.com/diagrams/notation)。

- タイトルに、図の種類、対象、状態（To-Be の案、As-Is）、時点を書く。
- 凡例を置く。線の実線と破線、線の色、枠の種類が何を表すかを書く。
- グループは、クラウド、アカウント、リージョン、VPC、サブネットの順に入れ子にする。Kubernetes の cluster と namespace は、VPC の中に置く。
- アイコンは公式のものを使い、色を変えない。大きさは図の中で揃える（AWS は 56、Kubernetes は 50x48）。
- アイコンのラベルは、アイコンの下に 2 行までで書く。サービスの正式の名前を使う。説明は吹き出し（付箋）に移す。
- 文字は 12px 以上にする。
- 線には、何を流すかとプロトコルを書く（`PostgreSQL（TLS）`、`OIDC（HTTPS）`）。「使う」のような一語にしない。
- リクエストが流れる線は実線、起動、取得、補助の線は破線にする。矢印は開いた形（`endArrow=open`）にする。
- 線を交差させない。アイコンとラベルの上を通さない。出る位置（`exitX`、`exitY`）と入る位置（`entryX`、`entryY`）を指定し、経由点で直角に曲げる。
- 線を省くときは、吹き出しに「〜も使う（線は省略）」と書く。
- 未確定のものは、ラベルに「（案）」「未決」「未確認」を付ける。確定したものと見分けがつくようにする。
- 背景は白にする。スクリプトが、draw.io の `light-dark()` の色を明るい側に固定する。

## モデルの書き方

- グループの子の座標は、親からの相対の座標である。絶対の座標で配置を決め、子を置くときに親の座標を引く。手で相対の座標を足し算すると間違える。
- 要素が多い図は、`mxCell` を並べる生成のスクリプトを作業の出力の置き場に書き、そこから `.drawio` を出す。直すときは生成のスクリプトを直す。
- 線は `parent="1"` に置く。端点はグループをまたいでも `source` と `target` で指定できる。
- ラベルに HTML（`<b>`、`<br>`）を使うときは、スタイルに `html=1` を付け、値は XML の属性としてエスケープする。

## 描画と確認

```bash
node <スキルのディレクトリ>/scripts/render-drawio-svg.mjs <入力> <出力.svg> --png <確認用.png>
```

- 入力は `.drawio`（圧縮しない形式）か、編集できる SVG である。SVG を入力にすると、図を直した後の描画し直しに使える。
- agent-browser が要る。コマンドが `agent-browser` で動かない環境では、`AGENT_BROWSER_CMD` で差し替える。
- 終了コード 1 は引数か入力の誤りである。圧縮した `.drawio` は、draw.io で圧縮しない形式に保存し直す。
- 終了コード 2 は描画の失敗である。agent-browser と viewer.diagrams.net に届くかを確かめる。
- `--png` の画像は、必ず開いて見る。XML が正しくても、線と文字が重なることがある。

## 置き場

- 置き場と名前は、リポジトリの AGENTS.md と context、ノートの vault の添付の規則に従う。
- 添付のファイルの名前を自動で変えるプラグインのある vault では、規則の形の名前で置く。後から変わると、埋め込みのリンクが外れる。
- 拡張子は `.svg` にする。`.drawio.svg` は、拡張子で編集の画面を選ぶツールで、編集できる SVG だと分かる。
- アカウント ID のような公開しない値を含む図は、draw.io の Web のアプリに上げない。手元のアプリで開く。

## 利用者が編集するとき

- 利用者に、編集に使うアプリと開き方を伝える。クラウドのアイコンを使った図は、draw.io のデスクトップのアプリかエディタの拡張機能で編集する。
- Obsidian の Diagrams プラグインは、クラウドのアイコンを使った図を表示できるが、編集できない。条件は [references/obsidian.md](references/obsidian.md) にある。
