# fix-global-harness

global の規約とスキルは、apm のパッケージ global から配置している。誤りはその場で回避して終わらせず、元のファイルに書き戻す。

## 配置先を直さない

- `~/.claude/skills/`、`~/.agents/skills/`、`~/.claude/rules/`、`~/.claude/hooks/`、`~/.codex/AGENTS.md` は apm が写した複製で、symlink ではない。直しても次の配置で上書きされる。
- 配置先は、誤りの場所を特定するためだけに読む。

## 元のファイルを探す

- パッケージの場所は、`~/.apm/apm.yml` の依存にある手元のパスで確かめる。公開するパッケージと、公開できない値だけを持つパッケージの 2 つが並ぶことがある。
- 元のファイルは、各パッケージの次の場所にある。
  - 規約: `.apm/instructions/`
  - スキル: `skills/<名前>/`
  - output style: `output-styles/`（apm の外。直したら `~/.claude/output-styles/` へ複製し直す）
- どのパッケージの下にも同じ名前がなければ、依存から来たスキルである。どの依存から来たかは、各パッケージの `apm.yml` で見分ける。
  - agent-harness のほかのパッケージにあるスキル（write-prose など）は、agent-harness の `packages/<名前>/skills/` を直す。

## 直す

- 直す前に、何が、どのファイルのどの行と食い違ったかを 1、2 行で利用者に示す。
- 書き方は、パッケージがあるリポジトリの AGENTS.md と context に従う。
- global には、どのリポジトリでも成り立つことだけを置く。特定のリポジトリだけの内容なら、そのリポジトリの context を直すよう利用者に伝える。
- 公開するパッケージには、公開できない値（非公開のリポジトリのパス、公開していない製品やテーマの名前）を書かない。その値を含む規約とスキルは、公開しないパッケージに置く。
- 手順の組み替えや責務の移動に及ぶときと、`adr/` の判断を覆すときは、利用者の承認を得てから進める。

## 配置し直す

- コミットすると、lefthook の post-commit が `packages/global/` の変更を見て、`apm install -g` と `apm compile -g` を実行する。pull したときも post-merge で同じく動く。
- コミットせずに試すときだけ、`apm install -g` と `apm compile -g` を手で実行する。`apm compile -g` は `~/.codex/AGENTS.md` を書き出すので、規約を直したときは省かない。
- apm がないか、`~/.apm/apm.yml` にそのパッケージがないと、フックは配置を飛ばして標準エラーに出す。配置されていないので、原因を利用者に伝える。
- リポジトリを指す依存（手元のパスでない依存）は、push した後に `apm update -g` を実行するまで配置先に届かない。
- 配置先を開き、直した内容が反映されたかを確かめる。
- コミットは、パッケージがあるリポジトリの CONTRIBUTING.md に従う。

## サードパーティの誤り

サードパーティのスキルとプラグインは書き換えない。次の導入で戻る。

- 上流で直っていれば、`apm update -g` で進めるか、`apm.yml` の依存の固定（`#<sha>`）を差し替え、配置し直す。
- 直っていなければ、上流へ報告する文面を利用者に渡す。差し替えるか依存から外すかは、利用者が決める。
- 誤りを補う指示を、自分の規約やスキルに足さない。上流が直したときに食い違う。
