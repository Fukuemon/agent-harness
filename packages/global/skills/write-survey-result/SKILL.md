# write-survey-result

調査の結果を、根拠付きの文書にまとめる。実装も修正もしない。

- 対象と論点が曖昧なまま探索を始めない。足りない点だけを利用者に尋ねる。
- 保存先と名前の付け方は、リポジトリの AGENTS.md と context に従い、なければ利用者に尋ねる。会話で返すだけでよいかも確かめる。

## 構成

雛形は [assets/survey-template.md](assets/survey-template.md) にある。節は `調査前の状況整理`、`TL;DR`、`調査結果`、`追加で確認が必要な点` の順に置き、対象に合わない小見出しは削る。文書に残すときは、末尾に調査の時点のコミットの SHA、ブランチ、調査日を書く。

## 根拠の書き方

コードに基づく説明には、すべて直下に根拠を付ける。

```md
- {説明}
  - `{path}:{line-range}` / [{host}]({blob_link})
```

- path はリポジトリのルートからの相対にする。複数のリポジトリにまたがるときは、どのリポジトリかも明示する。
- コードスパンで囲むのは、path と行範囲だけにする。リンクまで囲むと、リンクとして機能しない。
- 処理の流れは、番号付きの箇条書きの各項目の直下に根拠を入れ子で置く。
- 「依存している」「影響する」と書いたら、その依存点のコードを示す。
- 確かめていない点は「未確認」と書き、`追加で確認が必要な点` に移す。

## blob link を作る

このスキルの `scripts/blob_link.py` で作る。ホストとリポジトリのパスは git の remote から取る。`--ref`（省くと HEAD）は SHA に直す。ブランチ名のままだと、ブランチが進んで行がずれる。

```bash
uv run --no-project python {このスキルのディレクトリ}/scripts/blob_link.py <path> [<start>[-<end>]] [--remote origin] [--ref <commit>]
```

対象のファイルがある作業ツリーの中で実行する。終了コードごとの扱いは次のとおり。

- 0: 標準出力の URL を使う。
- 1: git が失敗した。標準エラーを読み、場所か引数を直す。
- 2: 引数の誤り。行範囲は `12` か `12-30` の形にする。
- 3: URL は出たが、コミットが `--remote` で選んだ remote の追跡ブランチになく、開けないことがある。利用者に伝え、push 済みのコミットを `--ref` に渡すか、path と行範囲だけを書く。

## 書き終えたら

引用した行範囲を読み直し、ファイルの行数に収まり、主張した定義や呼び出しを含むかを確かめる。
