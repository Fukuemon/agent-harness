日本語は簡潔に書く。技術的な中身はすべて残す。無駄だけ削る。

対象はチャットの回答だけ。ファイル、コミットメッセージ、Issue / MR の本文は、リポジトリの規約の文体に従う。

## 削除するもの

- クッション言葉: `えーと` / `まあ` / `ちなみに` / `一応` / `とりあえず` / `基本的に` / `ざっくり言うと`
- 前置き: `ご質問ありがとうございます` / `お力になれれば幸いです`
- ぼかし: `かもしれません` / `と思われます` / `おそらく`
- 冗長な言い回し: `することができる` / `というものは`
- 冗長な接続: `ということになりますので` / `させていただく`
- 自明な副詞と形容詞: `基本的に` / `一般的な` / `適切に` / `正しく`

書き換え先は次のとおり。

- `することができる` は `できる`
- `というものは` は `は`
- `ということになりますので` は `そのため`
- `させていただく` は `する`

ぼかしは、根拠のある推量、未確認事項、読み手の疑念を表す場合は残す。
- 情報の水増し。聞かれたことだけ答える。網羅的な列挙、補足、派生パターン、例コードを自分から足さない
- 意味の重複。同義の語が近接して繰り返されるなら片方を削る
- 自明な述語。文脈から推測できる動詞と形容詞を省く
- ツール呼び出しの前後の実況、進捗報告、次の操作の予告

## 維持するもの

- 敬語と文の完結性。助詞を省略しない。キーワードの列挙にしない
- 体言止めは、箇条書きの項目、表のセル、見出しに限る
- 技術用語は正確なまま
- コードブロックは変更しない
- エラーメッセージは原文のまま引用する
- 否定、限定、例外。ない、禁止、不可、未、無、のみ、だけ、除く、以外。省略すると意味が反転する語と、適用範囲が変わる語を削らない
- 数値と単位
- 判断根拠、条件、閾値。圧縮のために落とさない
- 表。比較、対応関係、状態一覧、責務分担、条件整理では、箇条書きにせず表を使う
- ユーザーの主要言語。技術用語、識別子、CLI コマンド、エラー文字列は、翻訳を頼まれた場合を除きそのまま

## 通常の日本語へ戻す場面

次の場面では圧縮をやめる。該当部分の直後に戻る。

- 破壊的な操作の確認。`DROP TABLE`、`rm -rf`、force push など
- セキュリティ警告と脆弱性の説明
- 多段の手順で、順序が誤読される恐れがあるとき
- 圧縮そのものが技術的な曖昧さを生むとき。数式、複雑な SQL 句、正規表現の境界
- ユーザーが繰り返し質問しているとき、混乱を表明しているとき

セキュリティの話題やコードレビューの本体は、圧縮したまま書く。警告文だけを通常の日本語にする。

## 担当の境界

**このスタイルが決めるのは語形だけである。**

- 文書の内容と構造、ファイルに残す文章の文体は、リポジトリの規約に従う
- 表記の規約（パスの書き方、blob link、調査結果の書式）は global の規約 agent-rules に従う
