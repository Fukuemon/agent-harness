# Agent Operating Rules

この端末で動くコーディングエージェントに共通の作法。  
リポジトリの `AGENTS.md`、`CLAUDE.md`、context と食い違うときは、リポジトリの側に従う。

## リポジトリと worktree

- リポジトリは ghq で管理している。パスは `$(ghq root)/<host>/<owner>/<repo>/...` の形で書き、リポジトリは `ghq list` で探す。ファイルシステムを走査しない。
- 同じリポジトリが複数のパスにあるとき（fork、別ホストへの移行）は、どちらを主に使うかを確かめてから触る。
- worktree は worktrunk（`wt`）で作り、消す。置き場所は `<repo>/.wt/<branch>`（ブランチ名の `/` は `-` になる）である。`git worktree add` とリポジトリの外への worktree は使わない。

## 作業の出力の置き場

- エージェントが作るファイル（調査の結果、レビューと検証の報告、中間の生成物、使い捨てのスクリプト）は、作業するリポジトリの `.ai-out/` に置く。
- scratchpad と `/tmp` には置かない。セッションが終わると消え、設計の文書や issue から参照できなくなる。
- 不要になったファイルは、自分が作ったものだけを 1 つずつ削除する。`.ai-out/` はディレクトリごと消さない。ほかのセッションの成果物が入っていることがある。
- `.ai-out/` が `.gitignore` にないリポジトリでは、先に `$(git rev-parse --git-common-dir)/info/exclude` に足す。worktree の `.git` はファイルなので、`.git/info/exclude` は開けない。
- ファイル名は `YYYY-MM-DD-<対象>-<種別>.md` にする。日付は当日にする。
- 利用者が置き場所を指定したときは、それに従う。

## ツール

- Python のランタイムは `uv` を使う。`pip` と `python -m venv` を直接使わない。
- `rg` の `-r` は置換のフラグである。`-rn "pattern"` はマッチを文字列 `n` に置き換えて出力し、偽の調査結果になる。行番号は `-n` だけで出る。
- CLI を新しく入れるときは、`mise` か devbox の global の宣言に足してから入れる。`go install`、`cargo install`、`npm -g` で入れない。

## コードの調査

- マッチした 1 行だけで判断しない。囲っている関数やブロックの全体を読む。手前の条件分岐を読まないと、分岐の 1 つを全体の動きとして書いてしまう。
- 複数のファイルを横断して検索したら、ヒットごとに、どのファイルのものかを確かめてから書く。同じ名前のファイルが別の階層に並ぶリポジトリでは間違えやすい。
- 引用する行の範囲は、引用の直前にその範囲を読み直す。検索の結果から転記しない。
- ツールの出力が不自然に短いときや揃いすぎているときは、結論に使う前にコマンドとフラグを確かめ直す。

## サブエージェント

- 広い探索、レビュー、分担できる下調べのように、独立した文脈が有利な作業はサブエージェントに任せる。依存のない調査は並べて投げる。
- サブエージェントには、何を返してほしいかを書く。返ってきた内容のうち、結論に使う部分は自分で確かめる。

## 書き方

- 会話の語形は、output style の `genshijin` に従う。
  - output style はサブエージェントに適用されないので、文章を書かせるときは語形を指示に書く。
- ファイルに残す文章は、リポジトリの規約とスキルの文体に従う。
- コードの調査の結果は、次の形で書く。
  ```md
  - {説明}
    - `{path}:{line-range}` / [{host}]({blob_link})
  ```
- blob link の ref には、ブランチ名ではなくコミットの SHA を使う。ブランチが進むと行がずれる。
  - GitHub: `https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<start>-L<end>`
  - GitLab: `https://<host>/<group>/<repo>/-/blob/<sha>/<path>#L<start>-<end>`
- コードスパンで囲むのは、パスと行の範囲だけにする。リンクを囲むと、リンクとして働かない。
- 事実と推測を分けて書く。確かめていないことは「未確認」と書く。

## 変更の安全

- 秘密の情報（トークン、認証情報）を、ファイル、コミット、issue、pull request に書かない。
- public のリポジトリに、公開しないリポジトリにだけある値を書かない。
- global の規約とスキルの誤りに気づいたら、その場で回避せず、スキル `fix-global-harness` で元のファイルを直す。
