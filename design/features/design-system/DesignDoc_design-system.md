# デザインシステム

## Overview

パッケージ design-system は、画面の見た目を意味のトークンだけで書くための取り決めと、それを使う側と保守する側の文書の型を持つ。全体像は [agent-harness Design Doc](../../DesignDoc.md) にある。

## Scope

- 持つもの: トークンの段の分け方、デザインシステムの文書（使う側の規則）の型、アクセシビリティの基準と確認の方法の表、カタログのページの構成と題の決め方、コントラストのテストの雛形。
- 持たないもの: トークンの値とブランドの色。元にする公開のデザインシステムの選択。コンポーネントの実装。

## Design

### トークンの段

トークンを 3 つの段に分ける。画面は意味の段だけを使い、基本の段の名前と色の値を書かない。

1. 基本: 元にするデザインシステムの値。
2. 意味: プロダクトの役割の名前（面、文字、枠、状態）。基本の段を指す。
3. テーマ: スタイルの仕組みに渡す名前。意味の段だけを指し、仕組みの既定の色と大きさを消す。

意味の段から、静的なファイル（画面仕様書のモック、文書のサイト）が読む CSS を生成する。生成物のずれは CI で確かめる。

### 文書

使う側の規則はデザインシステムの文書に、保守の判断は ADR に書く。文書の冒頭に、知りたいことごとの参照先の表を置く。  
カタログは、はじめに、トークン、コンポーネント、パターン、画面の 5 つのページに分け、題を配置先から決める。カタログに載せるのはダミーのデータだけにする。

## Interface

- 読むキー: `design_system.tokens_css`（意味の段から生成する CSS のパス）、`design_system.catalog_url`（公開したカタログの URL）。
- 写す雛形: デザインシステムの文書の骨組み、コントラストのテストの雛形。
