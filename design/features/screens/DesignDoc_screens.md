# 画面仕様書

## Overview

パッケージ screens は、画面ごとに、何を表示し、どの状態があり、どう操作できるかを、文書と操作できるモックで書く型を持つ。全体像は [agent-harness Design Doc](../../DesignDoc.md) にある。

## Scope

- 持つもの: 画面仕様書の規約とテンプレート、画面の ID の形、モックの共通のファイル（番号の印、デバイスの切り替え、属性で付ける操作、ワイヤーフレームの CSS）、規約の点検、画面仕様書を書くスキル。
- 持たないもの: 処理と通信（機能の Design Doc が持つ）。提供する機能の一覧（PRD が持つ）。トークンの値（design-system と利用者が持つ）。

## Design

### 画面ごとのファイル

画面ごとに 1 つのディレクトリを置く。

| ファイル | 持つもの |
| --- | --- |
| `index.md` | 状態ごとのタブ、構成要素の表（番号、種別、要素名、仕様）、要素ごとの節（値のソース、活性の条件、表示の条件、カタログ、操作） |
| `api.md` | 画面の型の項目と、API の項目の対応 |
| `mocks/` | 状態ごとに 1 枚の静的な HTML |

### モック

モックは静的な HTML を基準にし、コーディングエージェントが書く。デザインのツールのファイルは参照してよいが、基準にしない。  
モックは、トークンの CSS と共通の CSS だけを読み、外部の URL を読まない。要素に番号と、テストが使う識別子を付ける。テストの識別子は、モックに付けたものを元にする。

### 点検

規約の点検は、名前、番号、操作の属性、禁止の記述、テンプレートの消し忘れを見る。カタログの欄が指す story があるかと、テストの識別子がテストで使われているかは、キーで場所を受け取ったときだけ見る。

## Interface

- 読むキー
  - `screens.dir`: 画面仕様書の置き場。既定は `docs/screens`
  - `screens.tokens_css`: モックが読むトークンの CSS
  - `screens.catalog_url`: カタログの URL
  - `screens.e2e_dir`: テストの識別子を照らすディレクトリ
- 写す雛形: 規約、目次と画面の ID の規則、テンプレート、モックの共通のファイル。
