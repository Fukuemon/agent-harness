# ADR-0025: 写す先が利用者ごとに違う雛形は references/ に置き、キーはパッケージのスキルを初めて使うときにも尋ねてよい

## Status

承認

## Context

ADR-0023 で、アプリを作るための 5 つの関心をパッケージにし、雛形の置き場とキーの渡し方を決めた。  
5 つのパッケージを実装してレビューした結果、ADR-0023 の次の 3 つの判断と実装が合わなくなった。この ADR は、この 3 つを置き換える。

- 導入で必ず写す雛形は `assets/` に、利用者が選んで写す雛形は `references/` に置く。
  - デザインシステムの文書の骨組みと画面仕様書の雛形は、どの利用者にも写すが、写す先を利用者に尋ねる。setup-agent-harness は `assets/` を全部、同じパスへ写すので、`assets/` に置くと尋ねた先と違う場所にも写る。
  - setup-agent-harness は既にあるファイルを写さない。利用者が雛形を別の置き場へ移した後に導入のスキルを流し直すと、元のパスに雛形がまた写る。
- 値は、各パッケージの導入のスキルが利用者に尋ねて書く。
  - 画面仕様書のキーは 4 つで、読むのは画面仕様書を書くスキルとその点検だけである。導入のスキルを別に作ると、スキルが 1 つ増え、同じ手順が 2 つのスキルに分かれる。
- キーの一覧と schema は、各パッケージの Design Doc と `schemas/` が持つ。
  - 検証のパッケージのキー（エビデンスの置き場）は、スキルの本文だけが読み、スクリプトは読まない。core の schema は知らないキーを拒まないので、schema がなくてもチェックは落ちない。

## Decision

次の 3 点を決めた。

- 雛形の置き場は、写し方で分ける。
  - 導入のときに、どの利用者にも同じパスへ写す雛形は `assets/` に置く。
  - 利用者が選んで写す雛形と、写す先が利用者ごとに違う雛形は `references/` の下に置く。写すのは、パッケージのスキルか、スキルの `scripts/` のスクリプトである。
  - パッケージが直していくコード（モックの共通の JS など）を写すスクリプトは、既にあるファイルとの差分を示し、利用者が選んだときだけ上書きする。
- キーは、導入のスキルか、パッケージのスキルを初めて使うときに尋ねる。
  - キーを読むのがそのパッケージの 1 つのスキルとその点検だけなら、導入のスキルを作らない。そのスキルの「初めて使うとき」の手順で尋ねて書く。
  - 2 つ以上のスキルが読むキーや、CI への組み込みが要るパッケージは、導入のスキルを持つ。
- schema は、キーを読むスクリプトがあるパッケージだけが `schemas/` に持つ。
  - スキルの本文だけが読むキーは、Design Doc の Interface にキーの一覧と意味を書く。

## Considered Options

雛形の置き場の選択肢。

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 写す先が利用者ごとに違う雛形も `references/` に置く | 尋ねた先にだけ写る。導入のスキルを流し直しても、元のパスに写らない | 写すためのスクリプトか手順を、パッケージごとに持つ |
| `assets/` に置き、写した後に利用者が移す | 写す仕組みが setup-agent-harness の 1 つで済む | 流し直すたびに元のパスへ写る。移す手間が利用者に残る |
| setup-agent-harness に、写す先を尋ねる仕組みを足す | 写す仕組みが 1 つで済む | core が、ほかのパッケージの置き場のキーを知る必要があり、ADR-0013 と食い違う |

キーを尋ねる時点の選択肢。

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 導入のスキルか、パッケージのスキルを初めて使うとき | キーを読むスキルが 1 つのパッケージで、スキルを増やさずに済む | パッケージによって、尋ねる場所が違う |
| どのパッケージも導入のスキルを持つ | 尋ねる場所がそろう | 手順が 2 つのスキルに分かれ、読み込まれるスキルが増える |

## Consequences

### Positive

- 利用者が置き場を変えても、雛形が元のパスに写らない。
- パッケージが直したコードを、利用者が差分を見てから取り込める。
- 読まれないキーのために schema を保守せずに済む。

### Negative

- 雛形を写すスクリプトが、パッケージごとに要る。写し方の規則（既にあるファイルを飛ばす、差分を示す）は、それぞれのスクリプトが持つ。
- schema のないキーは、書き誤ってもチェックが見つけない。読むスキルが、値がないときに利用者に尋ねる。
