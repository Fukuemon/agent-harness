# ADR-0013: 共通の基盤はパッケージ core に置き、ほかのパッケージはそれを前提にする

## Status

承認。ADR-0009 の「パッケージ同士は依存させない」を、この決定が置き換える。

## Context

すべてのパッケージは、利用者のリポジトリの `context/project.yml` から自分の値を読む。  
このファイルと、AGENTS.md、CONTRIBUTING.md を利用者のリポジトリに置く導入のスキルは、文書の体系のパッケージに置いていた。  
その形では、ガードレールだけを入れる利用者も文書の体系の一部を借りることになり、「パッケージ同士は依存させない」と食い違う。

## Decision

次の 3 点を決めた。

- 共通の基盤を、パッケージ `core` に置く。中身は、導入のスキル `setup-agent-harness`、`project.yml`、AGENTS.md、CONTRIBUTING.md のテンプレートである。
- `docs`、`process`、`guardrails` は、`core` が置いた `context/project.yml` を前提にする。依存はこの 1 方向だけで、この 3 つは互いに依存させない。
- スクリプトの共通部分は、パッケージの間で共有しない。YAML の読み込みと、自分が読むキーの schema の検証は、各パッケージが自前で持つ。実行時に他のパッケージのファイルを探さないためである。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** `core` を置き、ほかはそれを前提にする | 依存が明示され、1 方向。基盤の責務が 1 つのパッケージに閉じる | パッケージが 4 つになる。`core` だけは外せない |
| 導入のスキルを文書の体系に置いたまま | パッケージが 3 つで済む | ガードレールだけの利用者が、文書の体系の一部を借りる |
| 導入のスキルを持たず、`examples/` の写しだけで入れる | パッケージ間の依存がない | 対話で値を埋められない。AGENTS.md と目次まで手で置く |
| スクリプトの共通部分も `core` に置き、実行時に読み込む | 同じ処理を 1 か所に持てる | 配置先のパスに依存し、`core` がないと他のパッケージのスクリプトが動かない |

## Consequences

### Positive

- 利用者は、`core` と、要るパッケージだけを入れる。`core` 以外は 1 つずつ外せる。
- 各パッケージのスクリプトは、単独で動く。

### Negative

- YAML の読み込みと schema の検証の数十行が、パッケージごとに重複する。
- `core` を入れずに使うには、`examples/` を手で写す必要がある。
